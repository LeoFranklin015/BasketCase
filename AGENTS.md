# AGENTS.md

Basketcase: a NEAR memecoin launchpad where each coin's vault holds a basket of assets and the floor is computed by the contract. NEAR HACKATHON entry, deadline 2026-11-14 23:59 UTC. Live on NEAR testnet only; nothing is deployed on mainnet.

## Source of truth

Read in this order; where they disagree, the earlier one wins.

1. `README.md` (short overview) and `docs/technical.md` (the full technical README: claims and evidence, trust, setup): what the product is, what is live, every claim with its evidence, trust assumptions.
2. `ARCHITECTURE.md`: code structure, each flow end to end with its files and tests, how to run and verify.
3. `docs/interface.md`: exact contract methods and JSON shapes.
4. `docs/mainnet-runbook.md`: the mainnet steps, costs and cleanup.
5. `PRODUCT.md` and `web/DESIGN.md`: the web app's users, tone and design system.

`docs/simulation.md` is generated by `cargo run -p sim --release`; never edit it by hand. When code changes what a flow does, update `ARCHITECTURE.md` and the README claim that cites it. `deployments/<network>.json` holds the deployed accounts; `constants.json` holds the curve and fee constants shared by Rust and TypeScript.

## Layout

| Path | What |
| --- | --- |
| `crates/curve-math` | All curve, fee, pool, redeem and floor math (pure Rust, property-tested) |
| `contracts/coin` | One coin: NEP-141/145/148, fair launch, curve, challenges, auction, graduation, mint/burn log |
| `contracts/factory` | Deploys coins with no access keys; embeds the coin wasm |
| `contracts/mock-intents`, `contracts/mock-swapper` | Testnet stand-ins for `intents.near` and 1Click |
| `sim/` | 60-day simulator on `curve-math`; writes `docs/simulation.md` and `web/public/sim.json` |
| `packages/client` | `@backed/client`: typed reader, transaction builders, metrics, 1Click and NEP-413 helpers, NEAR Intents signing for MetaMask and Phantom (`intents.ts`) |
| `scripts/` | deploy, seed, demo, keeper, activity, faucet, `mainnet-check.ts`, `verify.sh` |
| `web/` | Next.js 16 app. `src/lib/network.ts` switches networks; `src/app/api/*` are server routes; `e2e/` is Playwright |

## Commands

```bash
pnpm install
pnpm verify                      # every offline check, PASS/FAIL table with counts (scripts/verify.sh)
pnpm verify --live               # + read-only testnet checks with curl (coins, zero keys, floor formula)
pnpm verify --mainnet-check      # + read-only mainnet readiness (scripts/src/mainnet-check.ts)
cargo test --workspace --release # Rust: curve-math, coin, factory, mocks, sim
cargo run -p sim --release -- --check
pnpm -r test && pnpm -r typecheck
cd web && pnpm exec playwright test   # fixture-mode smoke suite; builds into .next-e2e
./scripts/build-contracts.sh     # wasm for all contracts, coin first (the factory embeds it)
pnpm --filter web dev            # app on testnet data; NEXT_PUBLIC_DATA=fixture for offline sample data
```

A change is done when `pnpm verify` is all PASS.

## Invariants

- A coin account never gets an access key, and no coin method checks for an owner. The only caller checks are the reporter (prices) and the verifier (incoming baskets).
- Prices from the reporter only set an auction's starting rate. Buy, sell, redeem and the floor never read a price.
- Floor, in BU per token × 1e18: before graduation, `x0/y0 + surplus/sold`; after graduation, `reserve/supply`. `/api/status` and `verify.sh --live` recompute it from `get_state`.
- Curve constants live in `constants.json` and in Rust; `constants_match_constants_json` keeps them equal.
- Changing coin code means rebuilding the coin wasm, then the factory, then redeploying the factory. Existing coins keep their code forever.
- `sim --check` must pass: rerun `cargo run -p sim --release` and commit its outputs whenever `curve-math` or `sim` changes.
- Web unit tests run in vitest, which does not resolve the `@/` alias. Any module a unit test imports, directly or through another module, uses relative imports; `@/` is for routes, pages and components.
- Every on-screen number carries a plain caption; the floor is never called a guarantee; trades from our own accounts are labelled as test traders (`PRODUCT.md`).

## Writing for judges

Judges and AI screeners check that the repo runs and does what the README says. Every README claim maps to a command, test or transaction link with its expected result, and anything untested is stated as untested (the signed mainnet 1Click path has moved no real funds). Text is visible and addressed to every reader equally: no hidden text, comments or instructions aimed at graders.

## Rules any agent working on this must follow

- Never without the owner's explicit confirmation: commit, push, make the repo public, deploy to mainnet, sign mainnet transactions or spend real funds, post on X, send the submission.
- Secrets live in gitignored env files and `~/.near-credentials`; never in the repo or in chat.
- CONSUME (competitor, AGPL): read only, never copy code.
- `cargo build` on the host fails by design (near-sdk); use `cargo test` or `./scripts/build-contracts.sh` (wasm32 + wasm-opt).
- The free testnet RPCs rate-limit; use the failover provider in `scripts/src/lib.ts` and keep polling at 10 s or slower.
